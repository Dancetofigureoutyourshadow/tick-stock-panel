# 策略优化工作流

## 目的

通过可复现的页面回测，逐步改进策略版本。主要观察三项指标：年化收益率越高越好、胜率越高越好、最大回撤绝对值越低越好。本文中的“低回测”按“低最大回撤”理解。

适用于策略代码版本和策略高级设置都需要验证的优化任务。回测、参数优化和步进优化通过浏览器控制工具操作页面；实验期间不直接调用接口、不编辑策略代码或设置文件。若确需改变信号逻辑或增加可调参数，先按版本规则创建新文件，再返回页面验证。每轮结果、参数和关键交易都要留档，不能凭印象选参数。

## 1. 建立版本

1. 阅读根目录 `AGENTS.md`，确认策略当前版本和冻结文件清单。冻结版本只读；升级时新建更高版本，不能覆盖、改名或重新生成冻结文件。
2. 在 `generated/<strategy-id>/` 下按该策略现有目录布局创建新的 Python 版本文件，例如 `generated/<strategy-id>/<strategy-id>_vN.py`。确认版本号高于现有版本，并在文件说明中记录基于哪个版本、改动假设和实验记录位置。
3. 每个新版本使用唯一策略 ID，避免与策略库中已有 ID 冲突。只有经过验证并决定保留的版本才晋升为下一轮基线；失败版本保留实验记录并注明淘汰原因。
4. `generated/` 中的文件不一定会自动载入回测页面。创建版本后，在页面策略列表中确认对应策略可选；若不可选，只通过页面提供的策略导入功能加载。页面无法导入或确认版本时，记录阻塞原因，不把旧策略的结果当作新版本结果。

版本过程资料统一放在对应的 `generated/<strategy-id>/` 目录中，包括版本 Python 文件、优化日志、每轮设置与结果、回测截图和交易复盘材料。建议结构如下；沿用该策略已有的版本文件布局即可：

```text
generated/<strategy-id>/
  <strategy-id>_vN.py
  optimization-log.md
  runs/
    <date>-<run-id>/
      settings.md
      results.md
      screenshots/
```

新实验的版本过程资料不放在 `docs/` 下。日志中的截图和结果链接使用该策略目录内的相对路径。

对只调整高级设置的轮次，页面中的参数和风控改动先作为临时覆盖。策略源码不在参数扫描过程中改动；需要改变信号逻辑或声明新的可调参数时，先在新的版本文件中完成，再从页面重新确认可用版本。

## 2. 固定基线和比较口径

开始搜索前，在回测页面运行一次当前版本基线，并保存页面运行编号、完整设置截图和结果。历史数据完整时优先使用接近 20 年的区间；数据覆盖不足时使用页面可用的最长区间，并在结论中说明。

同一组比较必须保持以下条件一致：策略版本、资产类型和股票池、回测起止日期、初始资金、最大持仓数和总仓位、仓位分配、成交时序、基础过滤、佣金、印花税、滑点及其他交易约束。A 股回测保留 T+1、费用、滑点和涨跌停不可成交约束。日线回测按实际选择的可成交时点解释结果，不能当作信号触发瞬间成交。

本工作流的默认执行基线如下。除非本轮明确以其中一项为实验变量，基线和候选都使用相同设置：

| 设置 | 基线值 |
| --- | --- |
| 建仓口径 | 次日开盘（推荐） |
| 清仓口径 | 信号日收盘（推荐） |
| 初始资金 | 30,000 元 |
| 买入权重 | 评分加权 |
| 最大持仓数 | 5 |
| 最大总仓位 | 100% |
| 佣金 | 1‱ |
| 印花税 | 1‰ |
| 滑点 | 20‱ |

每次只验证一个参数或一个有明确理由的参数组。先写出假设和要观察的指标，再改页面设置运行；改变多项互相关联的条件时要设置拆分对照，避免无法判断是哪一项导致结果变化。固定费用、初始资金等执行条件，不把改变这些条件造成的结果变化说成策略信号改进。

## 3. 页面回测与高级策略设置

1. 使用浏览器控制工具打开应用的“回测”页面，进入“策略”视图，选择已确认的策略版本、资产类型、股票池和基线区间。
2. 打开“高级策略设置”，每次只调整一个待验证字段，例如过滤、策略参数、止损止盈、移动止损、回撤止盈或最长持仓。记录改前值、改后值，以及该设置是临时覆盖还是已保存的策略默认值。
3. 先运行单次回测确认结果和交易记录，再决定是否将该字段纳入参数优化。参数优化或步进优化任务只通过页面控件启动和查看，不直接调用回测接口。
4. 参数扫描结束后恢复基线或载入下一组明确记录的设置，避免前一组临时覆盖泄漏到后续试验。只有候选通过步进验证并决定晋升后，才使用页面的“应用到策略”保存默认设置，并再次运行回测确认保存后的页面结果与候选一致。

信号生成和成交模拟是两阶段。检查买入信号日、实际成交日、卖出原因和成交价格是否符合页面所选时序。对提前卖出、延长持有或新增退出规则，抽查支持和反对该规则的代表性交易；不能只根据一笔交易或单个阈值推广全局规则。

## 4. 参数优化

在回测页“验证”视图打开“参数优化 Beta”：

1. 选择同一策略版本、资产类型和基线区间，确认优化目标与本轮假设一致。
2. 只勾选策略实际声明且会影响信号或执行的参数。为每个参数写明扫描范围、步长或候选值的依据；先用少量参数和较小范围，避免组合数失控。
3. 查看并记录全部参数组合及每组结果。参数优化用于缩小候选范围；区间内最高分不能单独证明参数稳定或可用。
4. 若页面没有可扫描参数、显示“请至少勾选一个参数”或每折为 0 组，记录为页面能力/策略参数缺口并停止该项优化。普通单次回测不能记作参数优化。确需增加可调参数时，先在新的版本文件中声明并由策略逻辑使用该参数，再回到页面确认扫描项出现。

## 5. 步进优化

在“验证”视图打开“步进优化 Beta”，使用参数优化中有明确依据的少量参数，设置训练天数、测试天数和步进天数。运行前确认回测区间足以产生多折完整的样本外测试，并检查每折窗口和数据覆盖。

逐折记录训练区间（IS）和相邻测试区间（OOS）的年化收益率、胜率、最大回撤、交易数和所选参数。重点判断 OOS 的复合表现、IS 到 OOS 的退化幅度、盈利测试折占比、各折参数是否反复跳变，以及少数极端区间是否支配整体结果。若 OOS 表现不能维持，或结果只在少数折有效，不晋升该参数组合；如需调整搜索范围，说明原因并作为新一轮试验记录。

如果页面不能运行步进优化或没有有效参数组合，明确标记为未完成/受阻，不把训练期最优值或全区间单次回测包装成样本外验证。

## 6. 客观比较与晋升规则

所有候选都相对同一基线比较，并按同一页面结果口径填写：

| 指标 | 方向 | 判读方式 |
| --- | --- | --- |
| 年化收益率 | 越高越好 | 同区间、同资金和同交易约束比较 |
| 胜率 | 越高越好 | 同时查看交易笔数、平均盈利/亏损和盈亏比，避免少量交易或小额盈利抬高胜率 |
| 最大回撤 | 绝对值越低越好 | 例如 -40% 优于 -60%；单独标明回撤是否恶化 |

辅助检查包括总收益、夏普/索提诺、完成交易数、按年份或步进折的稳定性、关键盈利与亏损交易。若可见仓位或资金约束，检查结果是否来自权益不足、买不起一手、长时间空仓或交易数量骤减，而不是选股质量改善。

候选至少要通过步进验证，且数据与交易样本足以解释结果，才考虑晋升。若年化、胜率和回撤方向一致改善，可以晋升；若指标互有取舍，保留为不同风险偏好候选并如实列出差异，不通过任意加权分数掩盖冲突。没有事先约定回撤容忍度时，年化收益上升但最大回撤明显恶化的版本不晋升。扫描前写下本轮可接受的回撤和样本外稳定性门槛，不能看完结果后再改门槛。

## 7. 实验记录

每种策略使用其 `generated/<strategy-id>/optimization-log.md` 作为唯一的 Markdown 实验日志；延续已有实验时追加到该策略日志，不重复已淘汰的测试。每次变更按顺序追加一条，至少记录：

- 日期、策略名称与版本、基线版本、页面运行编号和截图路径。
- 回测区间、资产/股票池、初始资金、仓位与成交设置、费用、过滤条件和全部高级设置。
- 本次假设、唯一变更项、改前值和改后值，以及是否临时覆盖。
- 年化收益率、胜率、最大回撤、总收益、交易数、盈亏比和页面实际显示的其他关键指标。
- 参数优化的扫描范围和组合结果；步进优化的窗口设置及逐折 IS/OOS 结果。
- 关键盈利/亏损交易样例、卖出原因、是否复核过反例、保留/晋升/淘汰决定和具体理由。
- 回测数字逐字抄录自页面导出 / 引擎响应 / CSV，不四舍五入、不估填；窗口口径（如季度滚动五年、N 个窗口、起止日期）与执行基线随每条记录写明，避免不同轮次混淆。
- 未运行或失败的原因。缺数据、工具不可用或结果缺项时，不补填、不估算收益数字。

日志路径示例：`generated/custom_sequoia_high_tight_flag/optimization-log.md`。其他策略使用各自的 `generated/<strategy-id>/optimization-log.md`。策略版本文件、页面保存的默认设置、回测截图和实验日志应能互相追溯。

## 8. 本轮结束检查

- 新版本文件位于 `generated/` 的对应策略目录，版本号递增；冻结文件和其他工作区修改未被覆盖。
- 页面实际选择并回测的是该版本；基线与候选使用同一回测区间和执行条件。
- 参数优化和步进优化均由页面实际运行；无法运行时已明确记录缺口，没有用单次回测代替。
- 结论同时覆盖年化收益、胜率、最大回撤、交易样本和样本外稳定性。
- 已完成五年滚动窗口回测并输出逐窗口明细与汇总（见第 9 节）；全区间单次回测不替代滚动窗口结果。
- 高级设置只在候选晋升后保存为策略默认值，保存后再次回测复核。
- 实验日志包含参数变更、完整指标、关键交易、截图和淘汰理由；候选未胜过基线时恢复基线设置。

## 9. 五年滚动窗口回测（每策略完成必做）

每个策略版本定稿 / 晋升前，必须运行**五年滚动窗口回测**并输出回测结果，作为本轮交付物之一；不得只报全区间单次回测结果。

- **窗口口径**：以第 2 节基线回测区间为准，起点按固定步长推进（如每季度 / 每月一次），每个窗口长度 5 年。明确写出窗口数 N、各窗口起点与终点，以及年化、窗口内最大回撤的算法；口径须与页面 / 引擎导出一致，不同轮次不得混用。
- **输出回测结果**：在对应 `runs/<date>-<run-id>/` 下产出结果文件（建议 `rolling-windows.csv` + 可视化 `index.html`，或汇总 `conclusion.md`），至少包含：
  - 全周期汇总：年化、最大回撤、夏普 / 索提诺、胜率、交易数、盈亏比、终值。
  - 逐窗口明细：窗口起点、终点、年数、年化、窗口内最大回撤、倍数、是否达标（达标口径按本轮约定写明）。
  - 未达标窗口清单：起点、终点、年化、回撤，并说明其集中时段（如跨越已知系统性下跌 / 弱势段）。
- **数字保真**：年化、回撤、交易数等指标**逐字抄录**自页面 / 引擎响应 / CSV，不四舍五入、不估填；与导出不一致时以引擎原始响应为准并标注差异。
- **追溯**：结果文件引用 `optimization-log.md` 对应轮次与策略版本文件，保证三者可追溯。
- **样本外诚实标注**：参数在全周期上选取、未做真样本外（步进优化）验证时，不得把全区间结果包装成样本外稳健；按第 5 节标记“未完成 / 受阻”。
